Rosmaster M3 Pro: как работают рука и одометрия

Все слайдеры живые. Числа руки взяты из кода (arm_model.py); параметры колёс ниже — типичные, их можно подогнать под ваш робот.

0. Живые данные с робота

выключено

1. Сервоприводы → углы суставов

Контроллер шлёт в шину «серво-градусы» 0…180 (у кисти и захвата другие диапазоны). Код переводит их в математические углы так:

q1 = −(s1 − 90)° q2..q5 = (s − 90)° q6 = s6 s = 90 → сустав в «нуле» (рука стоит вертикально)

Сырые значения серво (калибровка в controller-calibration.json) связаны линейно: raw = raw₀ + k·s. Прошивка отдаёт измеренные углы обратно (/arm6_feedback) — по ним мы стартуем из реальной позы.

2. Прямая кинематика (FK) руки

Плечо стоит в точке (x₀, z₀) = (0.0336, 0.218) м над центром базы. Звенья: L₂ = L₃ = 0.08285 м, кисть+захват L₄ = 0.1598 м. Рука работает в плоскости, углы суммируются:

θ₂ = −q₂, θ₃ = θ₂ − q₃, θ₄ = θ₃ − q₄ (знаки подобраны сверкой с кодом) x = x₀ + L₂ sin θ₂ + L₃ sin θ₃ + L₄ sin θ₄ z = z₀ + L₂ cos θ₂ + L₃ cos θ₃ + L₄ cos θ₄

3. Обратная кинематика (IK) и гладкое движение

Захват должен прийти в точку (x, z) с заданным наклоном φ. Сначала находим положение запястья, потом решаем двузвенник по теореме косинусов:

w = (x − L₄ sin φ, z − L₄ cos φ) − (x₀, z₀), d = |w| cos β = (d² − L₂² − L₃²) / (2 L₂ L₃) (нужно |cos β| ≤ 1, иначе точка недостижима) θ₂ = atan2(wx, wz) − atan2(L₃ sin β, L₂ + L₃ cos β), θ₃ = θ₂ + β

Слайдер «цель IK: x» выше двигает цель на высоте стола и рисует красным решение. Чтобы рука шла плавно, а не рывком, угол ведётся по профилю «минимального рывка»:

s(τ) = 10τ³ − 15τ⁴ + 6τ⁵, τ = t/T (скорость и ускорение в концах = 0)

Визуальное наведение: камера на руке видит куб, по глубине считается его положение в кадре, и рука подходит ступеньками по высоте h = 0.16 → 0.10 → 0.05 → 0 м, каждый раз перемеряя ошибку.

4. Меканум-колёса: из скоростей колёс в движение

Четыре колеса с роликами под 45°. Для радиуса r и K = lₓ + l_y (полуширина + полудлина базы):

vx = r/4 (ω₁ + ω₂ + ω₃ + ω₄) vy = r/4 (−ω₁ + ω₂ + ω₃ − ω₄) wz = r/(4K) (−ω₁ + ω₂ − ω₃ + ω₄) (1=пер.лев, 2=пер.прав, 3=зад.лев, 4=зад.прав)

5. Одометрия: колёса + гироскоп + лидар

Поза интегрируется из скоростей в мировой системе:

x += (vx cos ψ − vy sin ψ) dt, y += (vx sin ψ + vy cos ψ) dt, ψ += wz dt

Колёса проскальзывают (особенно меканум), особенно по углу. Поэтому угол берём из гироскопа, а накопившийся дрейф и позицию подправляет сопоставление лидарных сканов (ICP, scan_matching.py). Идея фильтра — комплементарная:

ψ_fused = α (ψ_fused + ω_gyro dt) + (1 − α) ψ_wheels, α → 1 на коротком масштабе

Ниже робот едет по квадрату 1×1 м. Красная — только колёса (с ошибкой масштаба и проскальзыванием в поворотах), зелёная — с гироскопом.

6. Заряд батареи

Тока нет, поэтому SoC считается по напряжению 3S с поправкой на нагрузку: V_ocv = V_meas + R·I_est, затем кривая 3.0…4.2 В на ячейку (≈9.0…12.6 В). Защиты на плате нет; программа лишь прерывает миссию ниже порога min_battery_v.
